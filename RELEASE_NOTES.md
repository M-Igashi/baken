# Bake'n Deck 4.5.0 - `expressport` writes artwork and hot cue colours, `headroom` flags damaged files

A minor release. `expressport` gains artwork, rekordbox's hot cue colours and an opt-in OneLibrary, names files on the stick the way rekordbox does, and handles a full or failing stick safely. `headroom` stops proposing a gain for a damaged file and keeps a WAV's own header, and `cdjsafe --check` knows seven more players. It is a minor rather than a patch because the library crates changed their public API (see "Library users"). If you re-export to a stick an earlier version wrote, read "Sticks written by an earlier version" below first.

## Highlights

- **Artwork with `--artwork`.** The picture embedded in each audio file goes onto the stick as its artwork: ID3 in MP3 and AIFF, the picture block of FLAC, the cover of M4A (not WAV). Every track with a picture gets the files rekordbox writes in `PIONEER/Artwork`, 80 and 240 pixels square, the picture fitted on black, encoded as rekordbox encodes them. On the reference export every FLAC and AIFF track rekordbox showed artwork for got it. A re-run writes only pictures that changed, and `--prune` cleans up `PIONEER/Artwork` too. Without the flag nothing changes ([#235](https://github.com/M-Igashi/baken/issues/235), [#247](https://github.com/M-Igashi/baken/pull/247)).
- **Hot cue colours.** Each of rekordbox's 16 hot cue colours goes onto the stick with the colour code and colour bytes rekordbox itself writes for it, measured on a rekordbox export with every colour set (light blue and cyan are inferred from the same palette). Up to 4.4.0 every colour but green went out as code 0 with the XML's RGB. Green and a hot cue without a colour are written as rekordbox writes its default green. The bytes are rekordbox's; how a player draws them has not been checked yet ([#236](https://github.com/M-Igashi/baken/issues/236), [#248](https://github.com/M-Igashi/baken/pull/248)).
- **OneLibrary with `--onelibrary`.** The stick also gets `PIONEER/rekordbox/exportLibrary.db`, the library the CDJ-3000X, XDJ-AZ, OPUS-QUAD and OMNIS-DUO read instead of `export.pdb`, built from the same tracks, ids and playlists. No OneLibrary player has read one yet, so it is opt-in and a report in [#139](https://github.com/M-Igashi/baken/issues/139) is welcome. Without the flag the stick keeps only `export.pdb`, as in 4.4.0 ([#244](https://github.com/M-Igashi/baken/pull/244)).
- **`headroom` no longer proposes a gain for a damaged file.** A reported AAC, corrupt from 3:41.7 to its end, failed the native decode, went to the ffmpeg fallback, which measured the garbage (+37.6 dBTP), and was offered -39.1 dB. Decoder errors are now counted, and a file with any, or measured above 0 LUFS or +20 dBTP, gets no gain and is listed with its full path and where the damage starts. The CSV report has a `Damage` column. A scan of a 1,873-file library found two more damaged AACs nobody knew about ([#223](https://github.com/M-Igashi/baken/issues/223), [#226](https://github.com/M-Igashi/baken/pull/226)).
- **A full or failing stick.** `expressport` used to fail every remaining track one by one when the stick filled up, then write `export.pdb` for what fit, report `Done!` and leave 0-byte files behind. Now the plan adds up what the run writes and stops before anything is written when the stick has less free space (also in `--dry-run`). A stick that fills up, goes read-only, stops answering or is unplugged mid-run ends the run with the old `export.pdb` in place, `export.pdb` and the settings files are replaced atomically, a failed copy removes its partial file, and `--prune` is skipped in a run with failed tracks ([#233](https://github.com/M-Igashi/baken/issues/233), [#241](https://github.com/M-Igashi/baken/pull/241)).

## Sticks written by an earlier version

- **Files on the stick are now named exactly as rekordbox names them ([#232](https://github.com/M-Igashi/baken/issues/232), [#239](https://github.com/M-Igashi/baken/pull/239)).** Names are cut at 48 characters including the extension (the cut used to be 43 characters of the name without its extension), artist and album folders are cut at 48 as well, a folder whose name ends in a dot gets `_` instead, and accented names are written in composed form (NFC) whatever form the tags are in. On a stick an earlier version wrote, the next export copies the affected tracks to their new place, about 8% of a library (49 of the 583 tracks in the four playlists of the reference export), and the old copies and their analysis stay until you export with `--prune`. Run the next export with `--prune` and every playlist you keep on the stick. A stick rekordbox exported to now has the same names, so `expressport` no longer writes second copies of these tracks there.
- **Audio that changed since the last export is replaced ([#231](https://github.com/M-Igashi/baken/issues/231), [#240](https://github.com/M-Igashi/baken/pull/240)).** A re-export kept the stick's copy whenever its size equalled the source's. `baken headroom` changes MP3 and AAC in place at the same size, so the stick kept the old audio under analysis made from the new one. A copy now stays only when 64 KiB at its start, middle and end also match the source. With `--cdjsafe`, a transcode on the stick is made again when it is cut short, is not 320 kbps CBR at 44.1 kHz, or was written less than an hour after its source last changed (the hour covers how macOS stores times on FAT across a clock change). `--cdjsafe` now probes every source with ffprobe, also on a re-run.

## Fixes

- **`headroom` keeps a WAV's own header and its `bext` chunk.** ffmpeg rewrote a 24-bit or faster-than-48 kHz WAV as `WAVE_FORMAT_EXTENSIBLE`, which turned `cdjsafe --check`'s ✓ into ? on every player, and blanked the Description, Originator and origination date of a Broadcast Wave file. The source's `fmt ` and `bext` chunks now go back after the gain; BWF v2 loudness fields are cleared, since they describe the audio before the gain ([#218](https://github.com/M-Igashi/baken/issues/218), [#224](https://github.com/M-Igashi/baken/pull/224)).
- **`expressport` rebuilds FLAC seek tables that no longer fit their file.** rekordbox's analysis of a FLAC carries a seek table, and a FLAC that changed after rekordbox analysed it (a `headroom` run re-encodes it) kept a table pointing into the old file; rekordbox's own export copies it as is. The plan lists such tracks, and the export rebuilds the table the way rekordbox writes it (508 of 559 unchanged library FLACs matched byte for byte) ([#219](https://github.com/M-Igashi/baken/issues/219), [#225](https://github.com/M-Igashi/baken/pull/225)).
- **CRC-protected MP3s keep a valid CRC after a gain change.** On an MP3 whose frames carry a CRC (`lame -p`), every gained frame failed its CRC check, 79 of 79 on a 20 s test file; now none do. mp3rgain 3.10.0 rewrites the CRC, and baken now requires it. MP3s without a CRC and AAC files come out byte-identical to 4.4.0.
- **A rekordbox XML written by Lexicon.** Lexicon writes the exact length in `TotalTime` (`341.8122448979592`), which `expressport` read as 0, so tracks with copied analysis had no length on the stick. It is now cut to whole seconds, as rekordbox writes it. `docs/dj-software-compatibility.md` has a new section on Lexicon's XML (set Convert keys to Musical key) ([#185](https://github.com/M-Igashi/baken/issues/185), [#249](https://github.com/M-Igashi/baken/pull/249)).
- **My Settings a player saved onto the stick are kept.** Every export copied rekordbox's settings files over whatever was on the stick. A settings file whose header names a player instead of rekordbox is now left as it is and listed in the plan, for example `DEVSETTING.DAT (CDJ-2000NXS2 1.85)`; files with rekordbox's header are replaced as before. Whether a player writes its own name when it saves My Settings is still open in [#234](https://github.com/M-Igashi/baken/issues/234) ([#250](https://github.com/M-Igashi/baken/pull/250)).

## Other changes

- **`cdjsafe --check` knows seven more players.** `--player <MODEL>` (repeatable, or `all`) checks against the CDJ-3000X, XDJ-1000MK2, XDJ-XZ, XDJ-RX3, XDJ-AZ, OPUS-QUAD and OMNIS-DUO as well as the three from before, each table from the player's own operating instructions. Without `--player` the output is as before, and the exit code follows the players asked for ([#220](https://github.com/M-Igashi/baken/issues/220), [#243](https://github.com/M-Igashi/baken/pull/243)).
- **`cdjsafe --check` reports lossy files that look transcoded from a lower bitrate**, with the measured cutoff ("nothing above 16.5 kHz, low for 320 kbps"): from 256 kbps below 19 kHz, from 192 kbps below 17 kHz. Report only; the exit code is unchanged. It decodes every MP3 and AAC track, so `--check` is slower (a 1,374-track playlist: 8 s to 35 s) ([#222](https://github.com/M-Igashi/baken/issues/222), [#229](https://github.com/M-Igashi/baken/pull/229)).
- **`djprofile.nxs`.** rekordbox puts `PIONEER/djprofile.nxs` on its sticks, and `expressport` now copies it from the settings directory when it is there. It is optional, and `--no-settings` leaves it out ([#238](https://github.com/M-Igashi/baken/pull/238)).
- **HFS+ sticks on a Mac.** The README documents Mac OS Extended (Journaled) with an MBR partition table as the faster choice on a Mac (a 62-track playlist: 260 s against 423 to 438 s on FAT32) and lists the players whose manuals do not list HFS+ (XDJ-R1, the first XDJ-RX, CDJ-400). The pre-flight warns about a case-sensitive HFS+ stick ([#221](https://github.com/M-Igashi/baken/issues/221), [#230](https://github.com/M-Igashi/baken/pull/230), [#246](https://github.com/M-Igashi/baken/pull/246)).
- The README mentions the Mac app's USB Export ([#217](https://github.com/M-Igashi/baken/pull/217)).
- **Size.** SQLCipher (for `--onelibrary`) and the image decoders (for `--artwork`) make the macOS arm64 binary 8.7 MB instead of 6.1 MB. `THIRD_PARTY_LICENSES.md` in every archive carries their notices.
- Dependencies: mp3rgain 3.10.0, rustls 0.23.45, thiserror 2.0.21, libc 0.2.189 ([#228](https://github.com/M-Igashi/baken/pull/228), [#245](https://github.com/M-Igashi/baken/pull/245)). CI: dtolnay/rust-toolchain ([#227](https://github.com/M-Igashi/baken/pull/227)); the crates are now published to crates.io with Trusted Publishing instead of a stored token.

New: `Measurement::damage()`, `Damage`, `DecodeErrors`, `MAX_PLAUSIBLE_LOUDNESS`, `MAX_PLAUSIBLE_TRUE_PEAK`.   - The mp3rgain requirement is 3.10.0.
- `baken-export`
  - New field `PlanTrack::stale_seek_table`; new `Plan::stale_seek_tables()`, `Report::seek_tables_rebuilt`, `Report::seek_tables_dropped` and the module `anlz::flac` (`TAG`, `seek_table`, `is_stale`) ([#225](https://github.com/M-Igashi/baken/pull/225)).

  - New fields `Plan::space_needed`, `Plan::space_available` and `Report::prune_skipped`, and a new variant `Error::NotEnoughSpace { needed, available }`, returned by `plan()` and `export()`. `export()` now also returns `Error::DeviceWrite` partway through the tracks, where it used to fail each remaining track and return `Ok`, and it no longer prunes in a run with failed tracks. Every `DeviceWrite` from `export()` means the stick keeps the library it had ([#241](https://github.com/M-Igashi/baken/pull/241)).
  - New fields `Options::onelibrary`, `Plan::onelibrary`, `Report::onelibrary_written`, `Report::onelibrary_error`; new module `onelibrary` (`FILE`, `write`); new constants `pdb::rows::{MASTER_DB_ID, TRACK_BITMASK, ANALYSED_BITS}` ([#244](https://github.com/M-Igashi/baken/pull/244)).

## Notice for users upgrading from 3.2.x or earlier: the default behaviour of `baken headroom` changed in 3.3.0

Up to 3.2.x, `baken headroom` only ever turned files **up**. Since 3.3.0 tracks above the -0.5 dBTP ceiling are turned **down** to it, so every track on the stick ends up at the same True Peak. Pass `--boost-only` for the old raise-only behaviour, and run with `--analyze-only` first if you want to see what would happen.
